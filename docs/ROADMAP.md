# 功能規劃

產品目標：把程式與架構學習連成「看教材 → 練習 → 記下理解 → 複習弱點 → 做出作品」的工作台。先支援 JavaScript／TypeScript，教材與題目由 Markdown／JSON 擴充；使用開源套件，不以付費 AI API 作必要條件。

使用者目前授權先做會員與相關服務。以下其他階段是規劃，尚未全部實作；優先順序依實際使用回饋調整。

## 已有基礎

- [x] 2 條路線、6 個單元、24 題；Markdown 教材、JSON 題庫及 Zod 驗證。
- [x] 選擇、填充、簡答文字規準與 JS／TS 實作題。
- [x] QuickJS WASM 隔離執行、多筆測資、資源限制與可停止執行。
- [x] 教材與編輯器 code highlight。
- [x] 整頁、段落與文字註記；本機保存、搜尋、JSON／Markdown 匯出。
- [x] GitHub Actions 驗證與靜態 build artifact；不自動公開部署。

## 下一階段：複習與學習路徑

| 功能           | 使用者體驗             | 最小可交付範圍                                         |
| -------------- | ---------------------- | ------------------------------------------------------ |
| 錯題本         | 快速找到上次卡住的概念 | 自動收錄未通過題，依題目版本去重，保留歷次作答         |
| 複習佇列       | 每天知道接下來練什麼   | 自評「不熟／模糊／熟悉」，簡單間隔排程與手動重設       |
| 題庫篩選       | 按需求挑題練習         | 題型、難度、標籤、未作答／錯題／已通過                 |
| 分層提示       | 卡住時逐步取得幫助     | 提示 1 → 提示 2 → 解析；記錄看過的提示，區分獨立通過   |
| 所有題型草稿   | 換頁回來可以接著作答   | 選擇、填充與簡答加上與 JS／TS 草稿一致的保存規則       |
| 收藏與待學清單 | 留下想回頭看的內容     | 收藏單元、題目、筆記；個人排序                         |
| 學習狀態       | 清楚區分看過和會做     | 已讀、已練習、待複習、手動信心分開呈現，不以閱讀當精熟 |

先用透明的規則做複習排程；不用 AI 推薦才能運作。驗收要涵蓋題目改版、舊成績保留與帳號隔離。

## 再下一階段：實作工具

| 功能           | 使用者體驗               | 技術界線                                                            |
| -------------- | ------------------------ | ------------------------------------------------------------------- |
| 自訂測資       | 自己驗證猜想與邊界       | 使用同一隔離 runner 與資源限制，不修改官方測資                      |
| 輸出差異       | 看出期望值與實際值差在哪 | 陣列／物件路徑、型別與值差異；大型輸出截斷                          |
| 作答歷程       | 比較前後解法與分數       | 保存題目版本、語言、程式與執行結果；可回復成草稿                    |
| TS 型別診斷    | 同時練習執行與型別       | Worker 內跑 TypeScript language service，清楚區分型別錯誤與測資失敗 |
| 除錯與補程式題 | 練讀碼與修正問題         | 新 discriminated union 題型、JSON schema、renderer、grader 與範例   |
| 自由練習場     | 不離開網站就能做小實驗   | 沿用 QuickJS；先維持同步函式，不假裝支援 DOM／npm／任意網路         |

完整 Node.js、資料庫及多人正式競賽需要可信任的伺服器 Judge 與額度管理，另行評估，不放進瀏覽器執行器假裝支援。

## 後續：架構教材與知識整理

- 互動模擬：cache hit／miss、queue、retry、timeout、並發與流量，參數改動後呈現行為；每個模擬明列假設。
- 架構情境題：依讀寫比例、延遲、故障與成本作取捨，評語引用題目的規準，不強制只有一種架構答案。
- 筆記 Markdown 預覽、程式 highlight、標籤與教材／題目反向連結；raw HTML 維持關閉。
- 全文搜尋與名詞表：搜尋教材、題目與自己的筆記，公開內容與個人資料分開索引。
- 作者工具：新增教材／題目的範本指令、本機預覽、失效連結與缺測資檢查；持續以 Git review 管理內容。

建議教材擴充順序：TS generics → React state／effects → Promise 取消與競態 → API／資料庫 → cache／queue 與架構取捨。

## 服務深化：同步、離線與會員管理

| 能力               | 實作前需要處理                                                                  |
| ------------------ | ------------------------------------------------------------------------------- |
| 自動跨裝置同步     | 操作 ID、重試、離線佇列、刪除墓碑、衝突副本、資料遷移與雙裝置測試               |
| 更改信箱／密碼     | 重新驗證、確認信、其他 session 處理；與現有 reset flow 分開                     |
| 刪除帳號與雲端資料 | 明確確認、匯出、後端刪除權限及 Auth／DB 刪除一致性；不能把 service_role 放前端  |
| 完整離線站點       | Service Worker、資源版本、快取更新、配額失敗與資料保存策略                      |
| 免費離線語意輔助   | 模型授權、繁中與程式術語評測、固定模型版本、下載大小、快取與低效能裝置 fallback |
| 正式部署           | 選定網址與免費額度、Auth redirect、HTTPS、公開註冊寄信與真實端到端驗證          |

離線模型採「逐得分點的語意輔助」規劃：與人工標註答案比較、逐題校準，回報可能漏判。cosine similarity 不當正確率，否定句／關鍵限制需要額外規準；模型下載或裝置不支援時仍可使用現有文字規準。

課程編輯後台、社群留言、公開排行榜與證書暫不優先。先讓學習與資料保存穩定，再決定是否增加管理與互動成本。
